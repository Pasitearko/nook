# nook解压缩：总体设计、需求确认与会话交接

> 状态：需求已确认（第 12～14 节），按第 15 节分阶段实现中；第 1 阶段（后台进程）已完成，见第 16 节。
> 第 1～11 节保留讨论时的原文，其中的“推荐”以第 12～14 节的结论为准。

## 1. 用户目标与不可静默缩减的范围

为现有 Nook 文件管理器新增完整的归档应用，名称为 **nook解压缩**，不仅是调用压缩命令的右键小工具。

用户提出的要求：

1. UI 审美统一，与 Nook 对齐。
2. 布局、样式、功能与 7-Zip 对齐；与第 1 条如何协调，见 Q1。
3. 能全功能替代现有 GNOME 归档管理器（File Roller），不能未经确认缩减为基础解压工具。
4. 压缩和解压参数详细、功能完整。
5. 动画流畅，技术栈避免明显性能瓶颈。
6. 全面兼容主流归档后缀、格式变体和文件名编码。
7. 窗口浮动打开，不默认平铺；大小与 Nook 文件选择器相近。
8. 接入 Nook 右键菜单：
   - **压缩…**：打开完整参数界面，可配置路径、格式及高级参数。
   - **解压到当前文件夹**。
   - **解压到…**：打开文件夹选择器指定位置。
9. 提供独立应用界面与启动器入口，无需先打开 Nook 或压缩包。

用户允许使用 grilling 追问不确定的产品决策。当前只授权调研和方案讨论，未授权开始实现。

## 2. 总设计思路

**Nook 的视觉语言 + 7-Zip 的布局与操作工作流 + 成熟归档引擎 + 独立任务系统 + 桌面集成。**

不自行开发压缩算法。继续使用现有 **Qt 6.8+ / Qt Quick / QML / C++20**，避免引入另一套 UI 技术。

```text
Nook 右键菜单                  启动器 / 双击压缩包 / 拖入文件
      └────────────────┬──────────────────────┘
                       ▼
                   nook解压缩
           独立窗口、应用身份、配置及启动入口
                       │
               归档控制器与任务系统
       条目模型 / 队列 / 进度 / 冲突 / 密码 / 取消
                       │
             异步 IPC + 非特权工作进程
                       │
          7-Zip / libarchive / 必要的补充后端
```

### 架构边界

- **Nook**：发现文件、传递选择和目标位置、发起动作。
- **独立归档应用**：格式识别、归档浏览、参数配置、任务生命周期、写入安全。
- **共享 UI 模块**：主题、图标、按钮、菜单、对话框、系统外观适配。需先从现有主程序抽取有限组件，不照搬整个文件管理器控制器。
- **文件选择器**：选择文件或目标位置；选择成功不代表目标已预留、可写或可安全覆盖。
- **FileManager1**：解压后显示结果位置；归档应用调用服务，不注册抢占服务名。
- **合成器规则**：在 niri 等平铺环境中保证浮动；应用侧尺寸设置本身不能保证非平铺。

### 后端决策仍待验证

考虑 7-Zip 与 libarchive 互补，但**尚未确定谁是基础后端、谁是补充后端**，也未确定全部采用库接口还是部分使用 CLI。

先验证：结构化条目列表、编码、加密和密码通道、分卷、更新能力、安全解压控制、进度、退出状态、取消及许可证义务。

- libarchive：结构化 API 和受控写入更适合作为基础能力候选。
- 7-Zip：高级 7z/ZIP 参数及格式兼容性的重要候选。
- 不允许通过普通命令行参数暴露密码，不拼接 shell 命令字符串。
- 独立进程隔离不等于文件系统沙箱，后者需要另外设计。

## 3. UI 与功能组织

### 独立主窗口

启动时提供“打开压缩包”“新建压缩包”和拖入区域。打开归档后采用：

- 顶部工具栏：添加、解压、测试、复制、移动、删除、信息。
- 地址栏及包内路径导航。
- 中央归档文件列表：名称、大小、压缩后大小、类型、修改时间等。
- 状态栏与任务入口。
- 搜索、排序、多选、键盘操作、拖入和拖出。
- 按格式能力启用修改功能，只读格式明确标识。

主窗口以现有选择器 **1102 × 709 逻辑尺寸**为设计起点，适配小屏和缩放；参数窗口更紧凑，允许调整大小。拟使用独立 app-id（例如 `local.nook.archive`），配套浮动规则，不复用 chooser 身份。

### 压缩参数窗口

常用参数直接展示，高级参数分组展开，随格式联动：

- 输出路径、文件名、格式。
- 等级、压缩方法、字典、字长、固实块。
- 线程数、内存估算及支持时的资源限制。
- 分卷预设和自定义容量。
- 密码、加密方式、文件名加密。
- 添加／替换、更新、同步等支持的更新模式。
- 包含／排除、路径保存方式、链接处理。
- 时间戳、权限及其他元数据、完成后测试。

仅显示引擎真正支持的参数，并解释兼容性及资源代价。

### 解压界面

目标目录、全部／选中、保留目录／平铺、覆盖策略、编码预览、密码、分卷提示、进度和错误详情。剩余时间仅在可以合理估算时显示。

暂停能力待验证，不把简单挂起进程等同于完善暂停；取消必须处理子进程树和残留文件。

### 完整替代的功能范围

除创建与解压外，还应纳入浏览、测试、属性、添加、删除、重命名、格式转换、外部应用打开包内文件、编辑后写回、多包批量处理、MIME 关联和默认应用设置。

## 4. 用户操作流程

### 从 Nook 压缩

选中文件／文件夹 → 右键“压缩…” → 带入全部选中项目 → 设置输出与参数 → 校验能力、路径和资源 → 入队 → worker 执行 → 显示进度与结果 → 可在 Nook 显示产物。

多选应使用模型的完整 `selectedUris`，不能只使用首个条目。搜索结果、跨目录选择、回收站和目标路径语义需专门定义。

### 解压到当前文件夹

选中归档 → 右键动作 → 确认实际目标及归档能力 → 必要时询问密码、冲突或风险 → 执行 → 显示结果。

是否自动新建同名目录，见 Q5；批量选中位于不同目录的归档时，目标规则待后续确认。

### 解压到指定位置

右键“解压到…” → Nook 风格文件夹选择器 → 确定目标 → 处理密码／冲突 → 执行 → 可打开目标目录。

选择器优先评估标准 portal 客户端接口；不能直接把 Nook 的 portal 后端私有接口当成应用公共 API，也不能假定所有 Qt 部署环境都会自动显示 Nook 选择器。

### 独立使用

启动器打开“nook解压缩” → 打开／拖入归档或新建 → 浏览、测试、修改、压缩、解压 → 独立管理任务，不依赖 Nook 主进程存活。

## 5. 兼容性、安全与性能原则

### 格式与编码

按“格式 × 读取／创建／修改／测试 × 加密／分卷／编码变体”维护能力矩阵，不能仅以扩展名列表宣称支持。

- 主要读写目标：7z、ZIP、TAR、常见压缩 TAR。
- 单文件压缩流与多文件归档明确区分。
- RAR/RAR5、分卷、ISO、CAB、CPIO、DEB、RPM 等按实际后端能力声明。
- 7-Zip 可解压 RAR，不代表可以创建 RAR。
- GNOME 长尾格式逐项核对，额外依赖策略见 Q2。
- 使用内容识别，不仅检查后缀。
- 文件名编码考虑 UTF-8、GBK／GB18030、Big5、Shift-JIS、CP437 等，支持手动选择和预览。
- 无标记旧归档不可能保证自动判断编码完全准确；必须处理转换失败和转换后重名。

### 安全

防路径穿越、绝对路径及链接逃逸；约束展开大小、条目数、磁盘余量；不自动执行包内程序；默认不恢复危险权限和所有者；普通用户运行；密码不入日志；临时文件安全提交，修改失败保护原归档。

逐文件原子写入不等于整个任务可回滚，取消后的保留／清理策略仍需确认。

### 性能

重任务不进 UI 线程；列表虚拟化、分批建模、进度节流、受控并发；复用 Nook 动效与关闭效果设置，验证软件渲染及真实 Wayland/GPU。

不承诺“零性能瓶颈”：算法、硬件和归档结构仍然决定性能上限。

> 每题回答“是”即接受推荐；不同意请说明替代方案。

### Q1 — 与 7-Zip 对齐：工作流还是旧式外观？

是否保留 7-Zip 式工具栏、列表、参数分组和操作习惯，但控件样式、间距、字体、颜色和动效全部使用 Nook 的设计，而不是复刻旧式外观？

**用户回答：** 只需要有7z的功能，外观完全可以自行设计

### Q2 — 全面替代 GNOME：是否接受可选依赖补齐少见格式？

主流格式随正式安装保证可用；ACE、ALZ 等长尾格式若需要额外工具，界面明确显示支持状态和缺少的依赖，不将不可用能力伪装成已支持。是否接受这种交付方式？

**推荐：是。**完整替代仍为验收目标，但不强制安装所有长尾工具，也不承诺后端做不到的能力。

**用户回答：** 这些特殊的长尾格式可以暂缓适配，先支持市面上大部分的主流zip、rar等等

### Q3 — 是否同仓库、同安装包，但提供独立可执行程序？

安装 Nook 后，启动器同时出现“nook”和“nook解压缩”；后者可以独立启动和工作，不依赖文件管理器窗口。以后仍可拆分软件包。

**推荐：是。**先共享主题与发布流程，减少版本和视觉分叉。

**用户回答：** 就合并一起，无需另外拆分软件包，后续有需求了再说

### Q4 — 新建归档默认 ZIP，同时提供醒目的 7z 预设？

例如“通用兼容：ZIP”“高压缩率：7z”“Linux 备份：tar.zst”，高级参数可以手动调整。是否采用？

**推荐：是。**默认 ZIP 方便分享，不让单一默认格式承担所有需求。备份预设仍须明确元数据保留范围。

**用户回答：** 可以默认zip，但是我想问下新建归档是什么？新建压缩包？如果是这个意思，那就把所有归档二字改成压缩，看的人云里雾里

### Q5 — “解压到当前文件夹”是否严格按字面执行？

归档内容直接落到压缩包所在目录，不自动套同名目录；另设可记忆的“智能新建文件夹”选项，包内有多个顶层项目时才创建同名目录。是否采用？

**推荐：是。**菜单语义清楚，智能防散落行为单独控制。

**用户回答：** 是，按你说的来

### Q6 — 关闭窗口时，是否默认允许任务继续？

有任务时提示“后台继续／取消任务／返回”，默认选后台继续；提供可重新打开的任务入口与完成通知，不只依赖托盘。是否采用？

**推荐：是。**避免误关窗口导致大任务中断，第一次清楚告知后台行为。

**用户回答：** 是的，关窗口不关任务，且要有完成通知的反馈

### Q7 — 密码是否默认仅在当前会话记忆，不永久保存？

允许本次批量任务共用密码，关闭应用后失效；长期保存若后续需要，则使用系统密钥环，不写普通配置文件。是否采用？

**推荐：是。**兼顾连续解压体验与安全。

**用户回答：** 应该让用户选择某些密码可以保存，以后需要密码时有下拉菜单可以直接选取并使用

### Q8 — 网络位置是否纳入完整支持范围？

除本地盘、移动盘和已挂载网络盘外，是否也支持 `smb://`、`sftp://` 等远程 URI？这通常需要本地暂存，修改后上传，并处理空间、传输与远端冲突。

**推荐：是，纳入最终目标。**明确显示暂存／上传过程与本地空间占用，不假装远程操作没有额外成本。

**用户回答：** 暂时不需要网络位置的功能，可以不做

## 18. 第 3 阶段：压缩／解压核心（已完成）

- **任务队列**（`TaskQueue`）：解压、测试、压缩都是任务；默认同时 1 个（设置里 1～4），其余排队，可提前／推后，可取消。进度、剩余时间、当前文件显示在任务卡片上。
- **任务抽屉**：标题栏右侧的进度环（显示进行中的数量，等待回答时变为琥珀色），点开在右下角列出所有任务；完成的任务可“打开位置”，取消或完成的解压可“删除本次已解压的内容”（移到回收站），提醒与错误可展开查看。
- **解压**：“解压到…”（Ctrl+E）对话框选择目标、整包或选中项、文件夹规则（需要时新建／总是新建／直接放入，默认需要时新建）、同名处理（询问／替换／跳过／保留两者），选择会被记住；“解压到此处”按字面放进压缩包所在文件夹；右键菜单可解压选中项到当前文件夹或“名称”文件夹。在包内子文件夹里解压选中项时去掉上层路径。
- **测试**：完整读一遍压缩包，结果写在任务卡片上。
- **新建压缩包**：紧凑的参数窗（`ArchiveCompose`，也可由 `nook-archive --compress 文件…` 打开，供第 4 阶段的 nook 右键菜单使用）。名称规则：单个项目用其名称（文件去掉扩展名），多个项目用所在文件夹名；保存到第一个项目所在的文件夹。格式 ZIP（默认）、7z、tar.gz、tar.xz、tar.zst、tar.bz2、tar，单个文件时另有 gz、xz、zst、bz2；六档压缩等级；ZIP／7z 密码（ZIP 默认 AES-256，可选兼容的 ZipCrypto；7z 默认加密文件名）；7z 分卷（100 MB、700 MB、1 GB、4 GB 或自定义）；“每个项目单独压缩”“压缩后校验”“压缩后把源文件移到回收站”（默认关、不记忆）。点击“压缩”后窗口转为进度，成功即关闭并通知，需要回答或失败时保持打开。拖入非压缩包文件、空窗口的“新建压缩包…”（Ctrl+N）也会打开它。
- **提问**：密码和同名冲突由发起任务的窗口询问；那个窗口已关闭（或任务不属于任何窗口）时，弹出一个只跟随该任务的小窗口（`ArchiveTaskWindow`），任务成功后自动关闭。
- **密码**：本次会话里用过的密码按压缩包记住，打开列表、解压、测试共用；输入密码时可勾选“保存到密钥环”并命名；对话框列出已保存的密码（名称 + 明文），点击即可填入；设置里可添加、删除；“自动尝试已保存的密码”默认关闭。没有 Secret Service 时无法保存，界面会说明。密钥环只在首次需要时读取（避免启动就弹出解锁）。
- **后台与通知**：关闭所有窗口后任务继续，进程在任务全部结束后退出，并发一条“在后台继续”的通知；任务结束时，若发起窗口不在前台（或是压缩参数窗），发送系统通知，成功的带“打开位置”，失败的带“查看详情”；可在设置里关闭。
- **设置**（标题栏齿轮，Ctrl+,）：同时进行的任务数、完成通知、自动尝试密码、已保存的密码。外观仍跟随 nook。
- **依赖**：新增 libsecret（必需）。
- **测试**：`archive-app` 增加队列（同名询问、智能文件夹、删除已解压内容、密码重试与密钥环、自动尝试、排序与并发、取消）、压缩请求（命名、等级、加密、分卷、单独压缩、源文件移到回收站）、压缩窗口端到端、主窗口解压与冲突对话框、无主窗口时的任务小窗、设置里的密码管理。

## 20. 第 5 阶段：完整管理（已完成）

本阶段补充的决策（已由用户确认）：

- **Q36 旧编码 ZIP**：文件名不是 UTF-8 的 ZIP 只能查看和解压，“只读”标记和灰掉的按钮说明原因，并提示“转换为 UTF-8 文件名的 ZIP 后即可修改”。
- **Q37 删除**：从压缩包删除前总是确认（红色“删除”按钮），文件夹连同内容一起删除，无法撤销。
- **Q38 临时文件**：打开、拖出的文件放在 `~/.cache/nook-archive/`（0700），退出时删除；启动时清理一天以前的残留。有未写回修改的会保留，并写入 `.nook-unsaved` 说明来源，不会被自动清理。
- **Q39 格式转换**：任何能读取的格式都能转换为 ZIP、7z 或 tar.*，沿用新建压缩包的参数（等级、密码、分卷、校验）；原压缩包保留，默认名称不与原文件重名，也不允许覆盖原文件。

实现：

- **哪些能改**：ZIP、7z、tar 及压缩的 tar；分卷、单文件压缩流、RAR 等其他格式、旧编码 ZIP、没有写权限的压缩包只读。原因显示在“只读”标记和按钮提示上（`ArchiveDocument.readOnlyReason`）。
- **添加**：工具栏“添加”→“添加文件…”／“添加文件夹…”（Nook 选择器），或把文件拖到打开的压缩包上，放进当前所在的文件夹；同名按设置询问，询问时标明“压缩包里已有的／要添加的”；同名文件夹合并。
- **删除**：工具栏、右键菜单或 Delete 键，确认后删除选中的项目。
- **重命名**：工具栏、右键菜单或 F2；预选不含扩展名的部分；名称为空、含“/”或与同一文件夹里的项目重名时不能确认。
- **改完即刷新**：添加、删除、重命名结束后，打开这个压缩包的窗口自动重新读取，停留在原来的文件夹。所有修改都先改副本，测试通过才替换原文件（Q19）。
- **打开包内文件**（Q21）：双击文件，解出到缓存目录后用默认程序打开；这一步不进任务列表。文件每次保存（短时间内的连续写入算一次），窗口都会问“写回”还是“不写回”；只读压缩包改为“另存为…”（选文件夹，重名时加编号）。关闭窗口时若还有没写回的修改，询问“全部写回”“放弃修改并关闭”或“取消”；选“全部写回”后窗口关闭，写回在后台完成。
- **拖出**：从列表拖动选中的项目，先解出到缓存目录，松开鼠标前解出完成即作为文件拖出（`text/uri-list`），可以拖到 nook 或其他文件管理器；拖回自己的窗口不做任何事。
- **转换格式**：工具栏“转换格式…”打开压缩参数窗的转换模式（不显示项目列表和“删除源文件”）；旧编码 ZIP 默认转换为 ZIP，文件名按当前选择的编码读取并存为 UTF-8。加密的源压缩包沿用本次会话的密码。
- **批量**：添加、拖入多个文件和文件夹一次完成；任务照常排队，可在任务抽屉查看。
- **测试**：`archive` 覆盖四种可修改格式的增删改、加密 7z、拒绝修改时原文件不变、转换保持文件名并可加密；`archive-app` 覆盖主窗口删除确认、重命名、添加与同名询问、打开文件后写回／不写回、关窗时的未写回提示、只读压缩包另存为、拖出导出、转换窗口与旧编码 ZIP 转换、拒绝覆盖原文件。
