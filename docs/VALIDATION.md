# 首版验证记录

日期：2026-10-28。环境：CachyOS、niri 26.04、Qt 6.12、原生 Wayland、Ryzen 7 9800X3D、RTX 5070 Ti。本文区分已完成的验证与仍需真实使用检查的项目。

## 功能验证

- CMake/Ninja 构建通过；核心与界面 CTest 套件通过。
- 核心场景包括：中文/大小写/特殊字符/非 UTF-8 名称的 URI 保留，取消过期目录请求，多选保持，复制和重命名，同名跳过/保留两者/取消，目录符号链接，真实跨文件系统移动，以及独立 D-Bus/GVfs 环境下的回收站移入和恢复。
- 索引验证包括：全拼/首字母、中文短词、文件类型、字面百分号、大小写不同的条目、排除缓存、循环符号链接、删除后核对、分页和过期查询丢弃。
- 预览验证包括：JSON、带引号的 CSV、Markdown 禁止远程图片、文本读取上限、图片缩放及损坏图片；另通过界面启动真实预览辅助进程读取文本。
- UI 使用真实鼠标/键盘事件检查新标签、双栏、列表选择、Ctrl+A 与地址栏焦点隔离、搜索、预览和设置。920 像素窄窗口检查按钮内容边界；原生 Wayland 也运行同一交互测试。
- 100%、125%、150% 缩放检查通过。分数缩放中发现并修复 SVG 栅格尺寸反馈到布局尺寸的错误；未通过增加图片内存上限掩盖问题。
- 标签使用整行容器内垂直居中，检查上下边距相等且至少 4 个逻辑像素，避免 ListView 重定位固定 y 偏移。
- QML 静态检查无运行属性/类型警告（父级未限定访问提示单独关闭）；桌面文件和打包脚本语法检查通过。

## 交互改进回归验证

- 空格打开/关闭预览，以及快速连续切换取消；预览标题拖动、边缘缩放，窗口缩小时保持可见。
- 列宽默认临时生效，离开目录恢复；「保存列宽」显式持久化，之后临时拖动不覆盖保存值；设置可恢复默认。
- 文件夹加入/移除快速访问、去重与持久保存；「打开方式」二级菜单及 `%U` 应用发现/实际启动；彻底删除确认弹框。
- 深色淡紫选中态、分类设置、索引范围两项输入同时编辑保存。
- 列表/网格滚轮加速和边界、触控板像素滚动不重复加速、窄双栏横向滚动；920 像素窄窗口及工具栏位置。
- 磁盘按分区类型过滤；本机仅识别两个 NTFS 数据分区（200 GiB、约 1.4 TiB），没有虚构第三个盘或挂载真实分区。
- 修复并覆盖目录缩短/排序后 Shift 范围选择锚点越界。

自动化截图保存在 `build/ui-*.png`。开机挂载配置已实现，纯逻辑与 mocked 测试不操作真实系统。真实授权、重启挂载和 Windows 休眠盘仍需人工验收，详见 [自动挂载说明](AUTOMOUNT-DESIGN.md)。

- 黄色文件夹、定制提示框、统一排序标题/下拉控件；双击使用系统默认应用，不自动弹出本应用的打开方式菜单。
- 网格图片缩略图和视频第一帧、较大图标、加载/失败时回退；损坏/透明文件、编码 URI、缓存和任务取消均有专门测试。ffmpeg 有限时、限像素和 768 MiB 地址空间上限；不宣称是完整安全沙箱。

- 六个 CTest 套件全部通过；followup UI 连续 10 轮通过。另在原生 Wayland/software 后端运行 followup UI，12 项通过（含初始化/清理），仅故意损坏图片的用例产生预期缩略图不可用提示。菜单测试等待弹层布局完成后再做坐标点击，避免无动画时 opened 信号早于布局完成的时序误报。

## 性能测量

测量由 `tools/benchmark.py` 在 `build/benchmarks/` 创建隔离样本；未扫描个人目录。目录测量使用真实本地文件、已热的文件系统缓存。索引测量使用一百万条合成文件名，不能当作所有实际搜索词的最坏情况保证。

| 项目 | 结果 |
| --- | --- |
| 一万项完整枚举与排序 | 40 ms |
| 十万项完整枚举与排序 | 408 ms |
| 一万项原生 Wayland 首次内容渲染（含程序启动） | 260 ms |
| 一百万条合成索引，特定文件名查询 | 3 ms，返回 1 项 |
| 一百万条合成索引，常见词查询 | 275 ms，首批 200 项 |
| 一百万条合成索引，两字符查询 | 88 ms，首批 200 项 |
| 单窗口空闲 60.24 秒平均 PSS | 127.74 MiB，峰值 127.80 MiB |
| 同一空闲测量的平均 CPU | 单逻辑核的 0.0996% |

空闲条件：原生 Wayland，普通小目录，视觉效果开启，没有扫描、预览或文件任务，因此没有活动辅助进程。PSS 受当前桌面共享库驻留状况影响。实际桌面模糊由 niri 决定，本次没有修改用户规则，也没有把额外合成器 GPU 开销计入应用进程 PSS。原始结果位于 `build/benchmarks/results.json` 和 `build/first-content.json`。

## NTFS 极速索引

- `nook-ntfs-tests`：合成 NTFS 镜像（两段 $MFT、属性列表与扩展记录、硬链接、DOS 名、孤儿记录、稀疏日志头、V2/V3 USN 记录）上的解析、300 轮随机损坏不崩溃；`SearchIndex` 从文件表建库、日志重放（文件夹改名带动其下未改动文件、删除、新建、改名）、日志被重建时整表重读、授权失败时退回逐目录扫描。
- `volume-helper`：助手与授权规则只用 fixture 测试（UUID 校验、只接受块设备、描述符传递、规则只授予单一用户与单一只读动作、不删除他人规则），不申请授权、不打开真实分区。
- 实机（`pkexec build/nook-ntfs-probe --index /dev/nvme0n1p3 DB`，打开分区后立即降回普通用户）：Windows 分区 1,058,048 条 MFT 记录 → 699,345 个索引项，首次建库 31.5 秒；随后一次日志复核 249 ms。数据盘 442,880 条记录的文件表读取 0.4 秒。

## 侧栏最近位置与文件任务（0.1-2）

- 移除侧栏索引数量卡片；平时显示最多 5 个去重的最近文件夹，空记录时隐藏，点击在当前激活栏打开。
- 只记录成功的本地目录导航，目录刷新、排序与启动恢复不重排记录；支持清空，关闭记录时同时删除已保存历史。同一进程的多窗口共享增删与清空通知，清空也取消尚未完成的记录请求。
- 文件操作期间显示任务状态、所选项目完成数和取消入口。普通文件传输使用 GIO 字节进度；递归目录不预先遍历统计，显示不确定进度，未完成时不显示 100%。任务仍在执行时即发布错误，可从任务卡片打开详情，任务结束后继续可从底部入口查看。
- 索引数量、更新/停止、状态与警告移至「设置 → 搜索与索引」；数量使用整数与本地化分组，不再显示科学计数法。
- 最近列表有独立滚动区域，按侧栏可用高度收缩；920×640、150% 缩放、5 项记录时保留导航空间，能滚动点击末项。
- 九个 CTest 套件通过，包括新增进度测试、最近位置多窗口持久化/隐私测试及侧栏与设置交互回归。新增交互另在原生 Wayland/software 后端验证。截图保存在 `build-nook/ui-recent-locations.png`、`build-nook/ui-recent-small.png`、`build-nook/ui-task-progress.png` 与 `build-nook/ui-index-settings.png`。

默认关联、Nautilus、FileManager1、系统文件选择器和 niri 配置均未修改。
