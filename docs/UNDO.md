# 文件操作撤销

## 交互与范围

- 空白区域右键菜单第一项根据最近一条可撤销记录显示 `撤销移动“文件名”`、`撤销删除“文件名”`、`撤销粘贴“文件名”` 等，批量任务显示首项名称和项数。没有记录或正在执行任务时禁用。
- `Ctrl+Z` 使用同一入口；编辑地址、搜索、名称等文本时不抢占文本编辑器的撤销。预览、菜单或对话框打开时不触发文件撤销。
- 原最近访问卡片改为“撤销历史”，最多 5 条会话内成功操作，最新在上，可点击任意一条单独撤销，无需先撤销较新的记录；成功后只移除所选记录，其余记录保留原顺序。小窗口内可滚动。没有记录时自动隐藏整个卡片，不显示空状态或占用布局空间；有记录时重新显示。
- 普通窗口共享同一个 Operations 和历史；应用进程结束后历史消失，不写入配置。清空记录只清空内存，不删除文件。旧版本的 `recentLocations` 和 `rememberRecentLocations` 配置会移除，不再追踪最近访问。
- 任务执行时该卡片继续显示原有进度、取消和错误入口，不增加第二个并行文件操作引擎。

| 正向操作 | 撤销动作 |
| --- | --- |
| 本地复制／粘贴 | 将实际生成的副本移到系统回收站，保留源文件 |
| 本地移动／剪切粘贴 | 移回原路径 |
| 本地重命名 | 恢复原名称 |
| 新建文件／文件夹 | 移到系统回收站；新建后若被编辑或新增内容则停止 |
| 本地移入回收站 | 从确切的回收站项目恢复到原路径 |

不支持：永久删除、覆盖替换、跨文件系统移动、非 UTF-8 文件名或包含此类名称的目录、远程操作、从回收站手动恢复、压缩器内部操作。不能安全确认的文件系统／回收站布局也不生成记录。任务状态会标明成功项中有多少项不支持安全撤销。支持“保留两者”的真实新名称，不会误处理原来的同名文件。

## 正确性策略

实现位于 `src/operations.cpp` 和 `src/undorecord.cpp`，UI 位于 `qml/RecentActivity.qml`、`qml/Main.qml` 和 `qml/SettingsPanel.qml`。

1. 在现有工作线程执行操作后，对成功的本地顶层项目记录真实目标路径、原路径、父目录身份和元数据指纹。失败／跳过项不入历史；成功项可在后续任务失败／取消后撤销。
2. 指纹使用设备号、inode、类型／权限、非目录的大小和纳秒修改时间、符号链接内容、目录树成员名称与身份，不跟随符号链接。目录不记录自身修改时间，允许“新建文件夹→在里面新建文件→依次撤销”正常工作。
3. 回收站匹配 Trash 规范的 `.trashinfo` 原路径与项目指纹，不依靠 basename 猜测，避免同名删除项目串号；恢复成功后移除相应 `.trashinfo`。
4. 每次撤销先预检整批：现有项目和父目录仍匹配、原路径不存在，之后按逆序执行。恢复动作使用 Linux `renameat2(RENAME_NOREPLACE)` 和固定的父目录 fd，不提供覆盖选择；即使预检后目标才出现也不覆盖。不支持该系统调用或需要跨盘时直接失败，不回退到复制／永久删除。正向移动／回收站操作会将父子重叠选择归并为最外层，避免产生无法逆序恢复的批次。
5. 按所选历史位置执行和更新记录，不将其后的操作一并回滚。文件已被后续操作改动、移动或原位置被占用时仍按上述预检停止；保留该记录，不妨碍选择其他记录，也不强制覆盖或自动撤销依赖项。记录以成功完成的反向项目为单位移除；撤销中途失败／取消时在原位置保留未完成项。已完成正向项目的有界日志扫描不因用户取消而中断；取消会阻止后续项目，但不会丢掉这一项。跨盘正向移动仍使用既有传输流程，不生成新的撤销记录，也可能使依赖旧 inode 的较早记录不可用；此时停止并保留文件，不尝试猜测新身份。
6. 不可丢弃到回收站的文件系统（例如某些系统内部 tmpfs）可能拒绝副本／新建撤销，届时保留文件和记录并报告错误，不降级为永久删除。

### 性能与边界

- 遍历和 GIO 操作均在现有文件操作线程，主线程只更新至多 5 条历史与状态。指纹是元数据扫描，不逐字节读取大文件；单棵树最多 200000 个节点，超限不记录，以避免无限扫描。目录深度也有限制。
- 这是会话内“撤销自己的文件操作”，不是文件版本备份、崩溃恢复或恶意并发写入防护。普通编辑／增删内容会被元数据检查拦截；如果外部程序刻意保持身份、大小、修改时间，元数据指纹不能证明内容未变。
- 外部程序可在预检后继续改动文件；文件系统无跨项目原子事务。恢复目标不覆盖，但不能承诺对抗检查与执行之间的所有竞态。
- 覆盖前数据未被备份，因此不承诺撤销覆盖；永久删除没有伪装成可撤销。暂不提供重做、跨重启持久历史或权限修改撤销；任意选取记录不代表能强制回滚已有依赖或文件冲突的操作。

## 验证

`tests/undo_test.cpp` 使用隔离 XDG 配置／数据／回收站，在构建目录所在文件系统生成临时文件。覆盖各类操作的非最新记录撤销、中间及最旧记录移除后顺序保留、无效索引与忙碌保护、所选批次的整批预检和重试、依赖冲突不阻塞其他记录、副本撤销、移动＋重命名链、新建目录嵌套撤销、保留两者、覆盖和永久删除排除、外部修改、整批占用预检和重试、父目录替换、悬空链接、同名回收站项目、符号链接不触碰目标、5 条上限、清空不删除、部分成功与取消、晚出现的恢复目标仍不覆盖、非 UTF-8 与 Unicode 替换字符名称同时存在不误操作、真实跨文件系统移动不入历史、父子／祖孙选择的两种顺序归并恢复。

`tests/followup_ui_test.cpp` 验证动态菜单真实点击、任意历史行真实点击、小窗口／高缩放滚动后点击旧记录、文本编辑与文件 Ctrl+Z 的隔离，以及列表／网格、开关动画时撤销悬停文件，确保已弹出／等待中的提示、选中框和悬停光效不残留，复用后的文件行仍可正常交互；`tests/core_test.cpp` 验证旧访问记录迁移和多窗口共享。
