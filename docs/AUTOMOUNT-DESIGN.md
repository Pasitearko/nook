# 磁盘开机自动挂载

已实现通过 **systemd + `/etc/fstab`** 的系统级开机挂载配置；不是在文件管理器启动时运行 sudo，也不是应用常驻服务。实现完成不代表已在本机应用配置：开发和测试没有改动真实 fstab、挂载真实分区或请求管理员授权。

## 使用与安装

1. 通过安装包安装程序、root 拥有的 `/usr/lib/nook/nook-mount-helper` 和独立 PolicyKit action `local.nook.mount`。依赖 `python`、`polkit`、`util-linux`、`systemd`；普通程序仍以当前用户运行。源码构建直接运行不会自动安装或授权 helper。
2. 打开「设置 → 磁盘与挂载」，查看固定 NTFS/exFAT 数据分区的名称、容量、UUID 和实际挂载点。每盘独立选择「开机自动挂载」和「只读访问」。默认不替用户选盘。
3. 点击「应用更改」，检查变更清单和 Windows 休眠风险，再选择「授权并应用」。系统执行管理员验证，程序不读取、记录或保存密码；取消授权不会写入配置。
4. helper 重新读取实际块设备与 fstab，完成验证后备份原配置并原子更新，运行 `systemctl daemon-reload`，只对本次启用的分区尝试挂载。不会执行 `mount -a`，也不强行卸载已经挂载在其他位置的盘。
5. 界面区分配置是否保存与当前挂载结果。运行时挂载失败可能发生在配置保存后，不能把失败提示当作自动回滚；需按提示检查系统状态。关闭自动挂载仅移除本应用管理的对应条目，不卸载、不删除挂载目录或盘内文件。

使用稳定目标 `/mnt/nook-UUID`，由 root 管理；不提供任意路径、shell 命令、调用者 UID/GID 或自定义挂载选项输入。NTFS 使用 `ntfs3`，exFAT 使用 `exfat`。示例（不是已应用的配置）：

```fstab
UUID=0123456789ABCDEF /mnt/nook-0123456789ABCDEF ntfs3 rw,uid=1000,gid=1000,umask=0077,nosuid,nodev,nofail,x-systemd.device-timeout=5s,x-systemd.mount-timeout=15s 0 0 # nook:v1 UUID=0123456789ABCDEF
```

UID/GID 从已授权的实际调用者解析，示例 1000 不是写死的运行参数。`umask=0077` 默认仅当前用户访问；只读时使用 `ro`。`nofail` 和有限超时避免缺盘阻塞正常开机。不使用 `noauto` 或 `x-systemd.automount`：目标是开机挂载，不是首次访问时挂载。

## 安全边界

- helper 拒绝非 root 执行、错误安装位置、不可信的 helper/父目录及无有效普通调用者身份的运行。专用 policy 仅授权该绝对路径，不给任意磁盘或命令无条件免密权限。
- 请求必须是限长、版本化 JSON，只允许 UUID、布尔启用值、布尔只读值；拒绝重复键、重复 UUID、未知字段和路径注入。
- 从真实设备重新校验固定磁盘父子关系、分区类型、文件系统、UUID 唯一性和系统挂载点。只接受固定普通数据分区；EFI、恢复、根分区、可移动盘、映射器和不支持的加密卷不配置。
- 仅修改带精确 `nook:v1` 标记的受管行，保留未选中行和其他原始内容。同 UUID、设备别名或目标目录已被其他条目使用时拒绝接管。
- 检查 fstab、挂载目录及元数据；拒绝符号链接、不安全权限、占用的挂载目标和不属于调用者的受管配置。备份和替换有并发检测，不以无条件覆盖方式写入。
- 授权进程和外部命令有输出/时间边界；超时不等于已授权操作必然没有执行，应刷新核对后再重试。

## Windows 双系统

Windows 快速启动、休眠或未正常关机可能导致 NTFS 无法安全读写。建议在 Windows 关闭快速启动并完整关机；可以明确选择只读，但仍服从驱动安全检查。程序不会使用 `force`、删除休眠文件、运行自动修复或更改文件系统状态，不能承诺任何盘状态下都能读写。

当前机器的只读识别结果是两个 NTFS 数据分区（200 GiB、约 1.4 TiB）和一个已挂载 Linux 文件系统。没有确认第三个 Windows 用户分区；未知专用分区不会被猜测为用户盘。界面始终按实际识别结果列出。

## 侧栏、索引与验证

侧栏快速访问和磁盘独立分组；应用完成后刷新实际挂载状态。索引只扫描实际挂载且可读的本地文件系统，不为索引主动挂载全部磁盘，不将未挂载空目录视为数据盘。

`tests/mount_helper_test.py` 使用纯解析/生成函数和 mocked 系统接口，验证请求边界、UUID/设备过滤、fstab 行保留与冲突、授权入口及部分失败反馈。测试不会写 `/etc/fstab`、运行 pkexec、mount 或 systemctl。首次真实授权、重启后的挂载、Windows 休眠盘、只读盘以及管理员同时编辑 fstab 的现场行为，仍需用户在明确授权后按真实环境验收。
